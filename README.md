# Kanji Repeater 📚

Kanji Repeater — система интервального повторения японских иероглифов через Telegram-бот. Данные, даты и уровни хранятся в Google Sheets определенной структуры, а Google Apps Script формирует очередь и обрабатывает ответы.

## Возможности

- поиск кандзи, которые пора повторить;
- общий дневной лимит для всех активных учебных листов;
- продолжение незавершённой сессии в течение дня;
- временное увеличение лимита на 5 или 10 кандзи;
- русский и английский интерфейс;
- выбор формы «Вспомнила/Забыла» или «Вспомнил/Забыл»;
- ежедневные уведомления и итоговая статистика;
- сохранение истории в листе `LOG`.

Подробное устройство проекта описано в [docs/general.md](docs/general.md).

# Установка

Установка выполняется через обычный интерфейс Google Sheets и Apps Script.

| 2 | Дата последнего повторения |

Данные начинаются с колонки `B`. Поддерживаются блоки, начинающиеся в строках `1, 6, 11, 16, 21, 26, 31, 36`.

В таблице используются служебные листы:

| Лист | Назначение |
| --- | --- |
| `CONFIG` | Список активных учебных листов |
| `SESSIONS` | Состояние сессий |
| `SESSION_ITEMS` | Элементы сессий |
| `LOG` | История ответов |

Скрипт читает результат формул и не рассчитывает интервалы самостоятельно. Точная структура листов приведена в [docs/sheets.md](docs/sheets.md).

## 2. Добавьте скрипты

1. На странице проекта в GitHub нажмите **Code → Download ZIP** и распакуйте архив.
2. Откройте свою таблицу и выберите **Расширения → Apps Script**.
3. Удалите пустой файл `Code.gs`, если он не используется.
4. Для каждого `.js`-файла из каталога [`scripts`](scripts) нажмите **+ → Script**.
5. Укажите имя исходного файла без расширения: например, для `Webhook.js` создайте `Webhook`.
6. Скопируйте код из соответствующего файла и сохраните проект.

Перенесите все `.js`-файлы. `appsscript.json` копировать вручную не нужно. Скрипты работают как единый проект, поэтому настраивать импорты не требуется.

## 3. Создайте служебные листы

1. В верхней панели редактора Apps Script выберите функцию `setupProjectSheetsV1`.
2. Нажмите **Run** и выдайте доступ к таблице.

Функция создаст отсутствующие листы `CONFIG`, `SESSIONS`, `SESSION_ITEMS` и `LOG`. Существующие листы и данные она не изменяет.

После создания откройте `CONFIG` и укажите названия учебных листов:

| SHEET_NAME | ACTIVE |
| --- | --- |
| 常用漢字1-3 | TRUE |
| 常用漢字4-6 | TRUE |
| 常用漢字7-9 | FALSE |

Название должно точно совпадать с названием вкладки. `TRUE` включает лист, `FALSE` исключает его из повторения.

## 4. Создайте Telegram-бота

1. Откройте в Telegram `@BotFather`.
2. Выполните `/newbot` и следуйте его инструкциям.
3. Сохраните полученный токен.
4. Откройте нового бота и отправьте ему любое сообщение.

Чтобы узнать Chat ID до настройки webhook, откройте в браузере:

```text
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```

Найдите число в `message.chat.id`. Не публикуйте токен, полный адрес запроса или полученный ответ.

## 5. Добавьте Script Properties

В редакторе Apps Script откройте **Project Settings → Script Properties** и добавьте:

| Property | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |
| `TELEGRAM_CHAT_ID` | Ваш числовой Chat ID |
| `MAX_DAILY_KANJI` | Дневной лимит, например `10` |

Остальные внутренние свойства бот создаёт автоматически.

## 6. Опубликуйте Web App

1. В Apps Script нажмите **Deploy → New deployment**.
2. Выберите тип **Web app**.
3. В поле выполнения выберите владельца скрипта.
4. Разрешите доступ без авторизации Google, чтобы Telegram мог отправлять webhook-запросы.
5. Нажмите **Deploy** и выдайте запрошенные разрешения.
6. Скопируйте URL, заканчивающийся на `/exec`.

Добавьте этот URL в Script Properties:

| Property | Значение |
| --- | --- |
| `TELEGRAM_WEBAPP_URL` | Полный URL опубликованного Web App с окончанием `/exec` |

Каждый пользователь должен создать собственный deployment и использовать собственный URL.

## 7. Подключите Telegram

1. В редакторе Apps Script выберите функцию `resetTelegramWebhookV1`.
2. Нажмите **Run**.
3. Разрешите доступ, если Google запросит его.
4. Отправьте боту `/start`.

Функция создаст секрет webhook, подключит Telegram к опубликованному Web App и зарегистрирует команды `/start` и `/menu`.

## 8. Настройте ежедневное уведомление

В Apps Script откройте **Triggers** и создайте триггер:

| Настройка | Значение |
| --- | --- |
| Function | `sendDailyReviewNotificationV25` |
| Event source | Time-driven |
| Frequency | Daily |
| Time | Удобное время |

Проверьте часовой пояс проекта. Он определяет смену дня, дневной лимит и срок действия сессии.

## 9. Проверьте установку

1. Запустите `sendDailyReviewNotificationV25()` из редактора Apps Script.
2. Убедитесь, что уведомление пришло в Telegram.
3. Отправьте `/start` и откройте повторение.
4. Отправьте `/menu` и проверьте переключение языка и формы обращения.

Кнопки ответа изменяют дату и Score реального кандзи, поэтому проверяйте их только когда готовы сохранить результат.

# Обновление проекта

После замены кода в редакторе Apps Script необходимо обновить опубликованное приложение:

1. **Deploy → Manage deployments**.
2. Откройте существующий Web App для редактирования.
3. Выберите **New version**.
4. Нажмите **Deploy**.

URL `/exec` останется прежним. Повторно запускайте `resetTelegramWebhookV1()`, если изменили URL deployment-а, параметры webhook или список команд Telegram.

# Известные ограничения

- Скрипт может работать напрямую с иероглифами из листа 組み合せ, но иероглифы-ссылки из других листов обрабатывает, как обычный иероглиф, то есть без учета того, что "под ним" находятся несколько иероглифов. Таким образом рекомендуется удалять ссылки на иероглифы листа 組み合せ из других листов, а этот лист добавить как отдельный в CONFIG
