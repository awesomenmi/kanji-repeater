# Проверка обработки карточек и webhook

## Локальная проверка

Из корня проекта выполните `node --test tests/*.test.js`. Тесты проверяют старые и будущие карточки, повтор после прерванной записи, а также отклонение запросов без секрета или из другого чата. Они не обращаются к Google Sheets и Telegram.

Тесты также проверяют кнопки увеличения лимита и продолжения сессии в обзоре, обработку ошибки Telegram API и отсутствие полного ответа API в журнале.

## Настройка перед проверкой в Telegram

1. Сделайте копию рабочей Google Sheets и используйте отдельный тестовый проект Apps Script, связанный с этой копией. Реальные ответы `ok`, `half`, `fail` изменяют дату и Score.
2. В Script Properties тестового проекта задайте `TELEGRAM_CHAT_ID` — ID личного чата пользователя, `TELEGRAM_BOT_TOKEN` и `MAX_DAILY_KANJI`. `TELEGRAM_WEBHOOK_SECRET` создаётся при первом запуске `resetTelegramWebhookV1()`. Не сохраняйте секрет в файлах проекта.
3. Отправьте код через `clasp push`, обновите версию Web App deployment и задайте `TELEGRAM_WEBAPP_URL` с URL тестового deployment `/exec` в Script Properties перед запуском `resetTelegramWebhookV1()`. В основном проекте функция по умолчанию использует URL рабочего deployment. Старые карточки без номера элемента после обновления webhook игнорируются.

## Проверка сценариев

1. На пустой тестовой копии запустите `setupProjectSheetsV1()`. Проверьте создание `CONFIG`, `SESSIONS`, `SESSION_ITEMS` и `LOG`. Повторный запуск не должен менять существующие данные.
2. Отправьте `/start`, откройте сессию и ответьте на первую карточку. Проверьте дату и Score кандзи, `SESSION_ITEMS`, индекс в `SESSIONS` и одну запись `OK` в `LOG`.
3. Повторно нажмите кнопку первой карточки после появления второй. Score и дата второй карточки не должны измениться, новая запись в LOG не должна появиться.
4. Ответьте на вторую карточку и убедитесь, что индекс продвинулся один раз, а LOG получил ровно одну запись для второй карточки.
5. Отправьте тестовый POST без `webhook_key` и с неверным значением: состояние таблицы не должно измениться. Повторите с правильным секретом, но другим `chat.id` или `from.id`: запрос должен быть отклонён.
6. Для проверки восстановления после ошибки используйте локальный тест `interrupted write resumes without applying score twice`. Не создавайте искусственный сбой на рабочей таблице.
7. Убедитесь, что системное меню содержит `/start` и `/menu` без дублирующей команды `/settings`. Откройте `/menu`, переключите язык на English и проверьте английский обзор и карточку. Верните русский язык, выберите «Вспомнил» и проверьте подписи кнопок и итоговой статистики.
8. Для проверки истечения создайте `ACTIVE`-сессию в тестовой таблице, измените её `Created At` на предыдущий день и отправьте `/start`. Сессия должна получить `EXPIRED`, её необработанные элементы — `CANCELLED`; новая дневная очередь не должна считать их резервом.

Если в LOG осталась запись `PENDING`, повторная доставка того же ответа должна завершить её как `OK`, не увеличивая Score повторно. Перед ручным исправлением такой записи сохраните копию таблицы и выясните причину сбоя в журнале Apps Script.
