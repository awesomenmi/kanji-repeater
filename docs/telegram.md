# Telegram и уведомления

# 10. Telegram

## 10.1. Формат интерфейса

Используются Telegram Rich Messages.

Базовые функции:

```javascript
telegramRequestV1(method, payload)
```

Универсальный запрос к Telegram API.

Функция проверяет HTTP-статус и поле `ok`. При ошибке выбрасывает исключение, а в журнал пишет только название метода, HTTP-статус и признак успеха, без полного ответа Telegram.

```javascript
telegramSendRichMessageV1(chatId, html)
```

Отправка Rich Message.

## 10.2. Webhook

Точка входа:

```javascript
doPost(e)
```

Выполняет:

* обработку `/start`;
* обработку `/menu` и `/settings`;
* обработку callback-кнопок;
* запуск или продолжение сессии;
* увеличение дневного лимита;
* обработку результатов;
* отправку следующей карточки;
* отправку статистики.

`doGet()` возвращает `OK`.

`doPost()` принимает запросы только с параметром `webhook_key`, равным Script Property `TELEGRAM_WEBHOOK_SECRET`, и только из личного чата, ID которого совпадает с `TELEGRAM_CHAT_ID`. При отсутствии этих свойств запрос отклоняется. Секрет нельзя размещать в репозитории или журнале. `resetTelegramWebhookV1()` создаёт секрет при первом запуске и регистрирует опубликованный URL `/exec` с этим параметром; после обновления Web App нужно вызвать эту функцию. URL `/dev`, который может вернуть `ScriptApp.getService().getUrl()` при запуске из редактора, для webhook не подходит. Для другого deployment URL можно задать через `TELEGRAM_WEBAPP_URL` в Script Properties.

После изменения кода webhook необходимо обновлять опубликованную версию Web App:

```text
Deploy
→ Manage deployments
→ Edit
→ New version
→ Deploy
```

Если используется прежний deployment, URL webhook менять не требуется.

Web App deployment обновлён через `clasp` до версии 47. После обновления deployment необходимо запустить `resetTelegramWebhookV1()` в редакторе Apps Script, если URL или секрет webhook изменились либо требуется зарегистрировать системное меню команд. Текущий URL `/exec` при обычном обновлении версии остаётся прежним.

Для диагностики регистрации используйте `checkTelegramWebhookV1()` из редактора Apps Script. Функция выводит ID deployment, совпадение секрета, количество ожидающих обновлений и последнюю ошибку доставки, не показывая сам секрет или полный URL.

## 10.3. Callback-команды

| Callback                  | Назначение                                        |
| ------------------------- | ------------------------------------------------- |
| `review:start`            | Начать или продолжить повторение                  |
| `review:start:<sheet>`    | Начать или продолжить повторение указанного листа |
| `review:<sessionId>:<itemIndex>:ok`   | Вспомнила для указанной карточки |
| `review:<sessionId>:<itemIndex>:half` | 50/50 для указанной карточки |
| `review:<sessionId>:<itemIndex>:fail` | Забыла для указанной карточки |
| `review:limit:+5`         | Увеличить сегодняшний лимит на 5                  |
| `review:limit:+10`        | Увеличить сегодняшний лимит на 10                 |
| `menu:review`             | Открыть обзор повторений                           |
| `menu:language:ru/en`     | Переключить язык интерфейса                        |
| `menu:gender:female/male` | Выбрать «вспомнила» или «вспомнил»                 |

Обработчик `review:limit` должен располагаться перед общим обработчиком `review:`.

Иначе команда увеличения лимита может попасть в обработчик результатов.

## 10.4. Rich-карточка

Функция:

```javascript
buildReviewRichHtmlV1(
  item,
  itemCount,
  sessionId
)
```

Карточка содержит:

* номер текущего повторения;
* кандзи;
* текущий Score;
* дату последнего повторения;
* три кнопки результата.

Кандзи является кнопкой копирования:

```html
<tg-button-row>
  <tg-button type="copy_text" text="命">
    命
  </tg-button>
</tg-button-row>
```

Отдельная кнопка «📋 Скопировать» больше не требуется.

### Дата последнего повторения

Функция получает её непосредственно из учебного листа:

```javascript
studySheet
  .getRange(
    Number(item.kanjiRow) + 1,
    kanjiColumn
  )
  .getDisplayValue();
```

Дата отображается в том формате, который установлен в Google Sheets.

Если ячейка пустая, показывается `—`.

### Центрирование

От принудительного центрирования отказались.

Не следует возвращать таблицы и `align="center"` без нового прямого запроса пользователя.

# 11. Ежедневное уведомление

Функция:

```javascript
sendDailyReviewNotificationV25()
```

Ежедневный триггер сохраняется на `sendDailyReviewNotificationV25()`. Функция отправляет основной обзор и автоматически создаёт одноразовый триггер `sendReviewReminderV1`. Вручную добавлять ещё два триггера не нужно. Дневной и автоматически создаваемые триггеры должны работать от одного владельца.

По умолчанию отправляется максимум **3 автоматических уведомления в день**, включая основное, с интервалом **120 минут**. Например, после основного уведомления в 09:00 следующие проверки будут примерно в 11:00 и 13:00. Apps Script может запустить триггер позже указанного интервала: [документация `after()`](https://developers.google.com/apps-script/reference/script/clock-trigger-builder#afterdurationmilliseconds).

Настройки в Script Properties:

* `DAILY_REVIEW_NOTIFICATION_COUNT` — общее число уведомлений, целое число от 0; по умолчанию `3`. `1` оставляет только основное, `0` отключает автоматические уведомления.
* `REVIEW_NOTIFICATION_INTERVAL_MINUTES` — интервал в минутах, положительное целое число; по умолчанию `120`.
* `DAILY_REVIEW_NOTIFICATION_STATE` — внутреннее состояние цепочки: дата, число попыток, ID следующего триггера и признак завершения. Не редактировать вручную.

Перед каждой повторной отправкой заново читаются сессии и дневная очередь. Уведомление отправляется, если есть незавершённая активная сессия либо доступные в пределах дневного лимита кандзи, повторение которых ещё не начато. Если таких элементов нет, цепочка прекращается без сообщения. Просроченные кандзи сверх дневного лимита сами по себе не вызывают напоминаний.

В один момент назначен не более чем один триггер напоминания. Повторный запуск ежедневной функции в тот же день не сбрасывает счётчик и не отправляет новое основное уведомление. Старая цепочка не переносится на следующий день по часовому поясу скрипта; следующий ежедневный запуск создаёт новую. Ошибка Telegram расходует попытку (доставка при сетевом сбое может быть неоднозначной), но оставшиеся попытки сохраняются. Поэтому при ошибках уведомлений может быть меньше заданного максимума.

Настройки перечитываются при каждом запуске. Изменение количества на `0` останавливает ожидающую цепочку при следующей проверке. Новое значение интервала применяется к следующему создаваемому триггеру. Уже завершённая цепочка не возобновляется до следующего дня.

### Разрешения до первого запуска по расписанию

После загрузки кода, **до ближайшего ежедневного запуска**, вручную предоставьте новые разрешения. Это нужно и при первой установке, и после обновления, добавляющего новые сервисы Google. `clasp push` и обновление Web App deployment не заменяют авторизацию владельца триггера.

1. Откройте **Расширения → Apps Script** из таблицы под тем Google-аккаунтом, который создал ежедневный триггер.
2. Сохраните обновлённый код. В списке функций выберите `getReviewNotificationSettingsV1` и нажмите **Run / Выполнить**. Эта функция только читает настройки: не отправляет сообщения, не создаёт и не удаляет триггеры.
3. В запросе авторизации нажмите **Review permissions / Просмотреть разрешения**, выберите аккаунт владельца триггера и предоставьте необходимые проекту разрешения. Для напоминаний обязательно разрешение `https://www.googleapis.com/auth/script.scriptapp` — управление триггерами Apps Script. Если интерфейс позволяет выбирать разрешения отдельно, не пропускайте его.
4. Если после подтверждения выполнение не продолжилось, снова нажмите **Run / Выполнить**. В разделе **Executions / Выполнения** убедитесь, что ручной запуск завершился успешно.
5. При первой установке затем создайте ежедневный триггер `sendDailyReviewNotificationV25`. При обновлении существующий ежедневный триггер сохраните: создавать дополнительные не нужно.

Фоновый триггер не может показать окно согласия и при отсутствии разрешения завершается ошибкой. Google рекомендует запуск функции из редактора для повторной авторизации: [Authorization is required](https://developers.google.com/apps-script/guides/support/troubleshooting#authorization-is-required-to-perform-that-action).

### Если уведомление уже пропущено из-за разрешений

При ошибке `You do not have permission to call ScriptApp.getProjectTriggers` выполните авторизацию по шагам выше. Можно также воспользоваться ссылкой «Нажмите здесь, чтобы предоставить разрешения» в сообщении об ошибке под аккаунтом владельца триггера.

Затем вручную запустите `sendDailyReviewNotificationV25()` для восстановления сегодняшней отправки и проверьте **Executions** и Telegram. В случае ошибки на первом `clearReviewReminderTriggersV1()` внутри ежедневного запуска код ещё не записал сегодняшнюю попытку, поэтому повторный запуск отправит основное уведомление и назначит напоминание, если повторение не завершено. Уже успешно начатую сегодня цепочку повторный запуск не сбрасывает. Разрешение само по себе не повторяет пропущенный запуск; состояние `DAILY_REVIEW_NOTIFICATION_STATE` вручную очищать не нужно.


Формирование обзора вынесено в `sendReviewOverviewV1()`. Webhook (`/start`, кнопки меню и изменение лимита) вызывает только эту функцию: ручные запросы не запускают цепочку и не расходуют лимит автоматических уведомлений. Изменения webhook вступают в силу после обновления версии Web App deployment; `clasp push` обновляет код для триггеров, но не существующее развёртывание.

Использует:

```javascript
getDailyReviewQueueV1()
```

Отображает:

* эффективный дневной лимит;
* количество выполненных повторений;
* количество доступных кандзи;
* количество оставшихся просроченных кандзи;
* количество зарезервированных элементов при необходимости;
* кнопки запуска новых повторений и продолжения активных сессий.

При достижении лимита уведомление не предлагает создавать новую сессию, но позволяет продолжить существующую.

Если есть дополнительные просроченные кандзи, могут отображаться кнопки:

```text
➕ Ещё 5
➕ Ещё 10
```

Нажатие передаёт callback:

```text
review:limit:+5
review:limit:+10
```

После успешного увеличения лимита webhook вызывает:

```javascript
sendReviewOverviewV1()
```

и отправляет обновлённое уведомление.

### Важная деталь

Количество всех просроченных кандзи и количество доступных в рамках дневного лимита — разные величины.

Нельзя показывать все просроченные кандзи как доступные для новой сессии.

# 12. Текущий сценарий /start

`doPost()` отправляет обзор через `sendReviewOverviewV1()`: дневной прогресс, доступные учебные листы, кнопки продолжения активных сессий и, если лимит мешает новым повторениям при наличии просроченных кандзи, кнопки увеличения лимита. Если после нажатия `review:start` новых элементов нет, бот повторно показывает обзор с причиной.

Старая кнопка `review:start` без имени листа выбирает сначала активную сессию, а при её отсутствии — первый активный лист из CONFIG. Новые кнопки передают имя листа явно.

## 12.1. Меню и настройки

`/menu` открывает меню с переходом к повторению, выбором русского или английского языка и формой русского обращения. `/settings` обрабатывается как скрытый совместимый псевдоним, но не показывается в системном меню Telegram. Настройки сохраняются в `TELEGRAM_USER_PREFERENCES` и применяются к обзору, карточкам и итоговой статистике. По умолчанию используются русский язык и женская форма.

`resetTelegramWebhookV1()` также вызывает `setMyCommands` и регистрирует команды `/start` и `/menu` в системном меню Telegram. После смены языка описания команд обновляются автоматически.
