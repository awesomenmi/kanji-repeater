# Структура Google Sheets

# 3. Структура Google Sheets

При первичной установке функция `setupProjectSheetsV1()` создаёт отсутствующие `CONFIG`, `SESSIONS`, `SESSION_ITEMS` и `LOG` с нужными заголовками. Существующие листы не изменяются. `FUNCTION` необходимо перенести из совместимой таблицы Kanji Reader.

## 3.1. Учебные листы

Примеры названий:

* `常用漢字1-3`
* `常用漢字4-6`
* `常用漢字7-9`

Количество учебных листов может увеличиваться.

Активность листов управляется через CONFIG.

### Структура блоков кандзи

Данные начинаются с колонки B.

Каждый кандзи занимает блок из пяти строк:

| Смещение | Содержимое                 |
| -------- | -------------------------- |
| 0        | Кандзи                     |
| +1       | Дата последнего повторения |
| +2       | Score                      |
| +3       | Countdown                  |
| +4       | Пустая строка              |

Начальные строки блоков:

```javascript
[1, 6, 11, 16, 21, 26, 31, 36]
```

Сканирование ограничено строкой 40.

Область начиная со строки 41 специальная и не должна обрабатываться стандартным сканером.

Символы `…` и `...` не считаются кандзи.

### Условия попадания в повторение

Кандзи считается доступным для повторения, если:

* его блок корректен;
* необходимые данные проходят проверку;
* Countdown является числом;
* Countdown меньше 1.

```javascript
countdown < 1
```

Countdown вычисляется формулой Google Sheets.

**Нельзя заменять формулу Countdown записью значения из Apps Script.**

## 3.2. CONFIG

Назначение: определяет активные учебные листы.

Структура:

| SHEET_NAME | ACTIVE |
| ---------- | ------ |
| 常用漢字1-3    | TRUE   |
| 常用漢字4-6    | FALSE  |
| 常用漢字7-9    | FALSE  |

Функция:

```javascript
getActiveStudySheetsV1()
```

Возвращает массив названий активных учебных листов.

## 3.4. SESSIONS

Хранит состояние сессий.

| Колонка | Поле          |
| ------- | ------------- |
| A       | Session ID    |
| B       | Created At    |
| C       | Status        |
| D       | Sheet         |
| E       | Item Count    |
| F       | Current Index |

Основные статусы:

* `ACTIVE`
* `COMPLETED`
* `EXPIRED` — незавершённая сессия, автоматически закрытая после смены дня

Одна сессия в текущей архитектуре относится к одному учебному листу.

Если активная сессия для листа уже существует, она используется повторно.

---

## 3.5. SESSION_ITEMS

Хранит состав сессии и результаты отдельных карточек.

| Колонка | Поле         |
| ------- | ------------ |
| A       | Session ID   |
| B       | Item #       |
| C       | Kanji        |
| D       | Sheet        |
| E       | Column       |
| F       | Kanji Row    |
| G       | Score        |
| H       | Countdown    |
| I       | Status       |
| J       | Result       |
| K       | Event ID     |
| L       | Processed At |

Статусы элементов:

* `PENDING`
* `PROCESSED`
* `CANCELLED` — необработанный элемент истёкшей сессии

Допустимые результаты:

* `ok`
* `half`
* `fail`

Event ID формируется следующим образом:

```javascript
sessionId + ':' + itemIndex
```

Номер карточки передаётся в callback. Обработчик сверяет его с текущим индексом сессии под Script Lock; ответ со старой карточки не применяется к следующей.

---

## 3.6. LOG

Постоянная история повторений.

| Колонка | Поле      |
| ------- | --------- |
| A       | Timestamp |
| B       | Kanji     |
| C       | Sheet     |
| D       | Column    |
| E       | Result    |
| F       | Old Score |
| G       | New Score |
| H       | Old Date  |
| I       | New Date  |
| J       | Status    |
| K       | Event ID  |

LOG используется для расчёта количества повторений за текущий день.

Журнал используется как журнал операций: новая запись получает статус `PENDING`, после завершения всех записей — `OK`. Если выполнение прервалось, повторный вызов завершает операцию по сохранённым значениям. Старые записи не удалять в обычном рабочем процессе.
