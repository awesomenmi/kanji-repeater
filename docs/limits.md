# Лимиты и очередь

# 7. Дневной лимит

## 7.1. Постоянный лимит

Хранится в Script Properties:

```text
MAX_DAILY_KANJI = 10
```

Значение 10 — использовавшееся в последних тестах. Фактическое значение может изменяться пользователем.

Функция:

```javascript
getMaxDailyKanjiV1()
```

Проверяет, что значение — положительное целое число.

## 7.2. Выполненные сегодня повторения

Функция:

```javascript
getTodayProcessedCountV1()
```

Читает LOG и считает записи:

* с датой текущего дня;
* со статусом OK;
* с уникальными Event ID.

Дата определяется в часовом поясе проекта Apps Script.

Для старых записей без Event ID используется номер строки.

## 7.3. Зарезервированные элементы

Функция:

```javascript
getReservedReviewItemsV1()
```

Находит `PENDING`-элементы `ACTIVE`-сессий, созданных сегодня.

Идентификатор элемента:

```javascript
sheetName + '|' +
column + '|' +
kanjiRow
```

Резервирование предотвращает повторное включение элемента в новую сессию.

Сессии предыдущих дней не резервируют элементы и не занимают дневной лимит. При следующем обращении к боту `expireOldActiveSessionsV1()` переводит их в `EXPIRED`, а оставшиеся `PENDING`-элементы — в `CANCELLED`.

## 7.4. Расчёт свободных мест

```javascript
remaining = Math.max(
  0,
  maxDaily -
  processedToday -
  reservedCount
);
```

Пример:

```text
Лимит: 10
Выполнено: 8
Зарезервировано: 2

Свободно: 0
```

Начатую сессию при этом можно продолжить.

# 8. Сортировка кандзи

Функция:

```javascript
getDailyReviewQueueV1()
```

Алгоритм:

1. Получить список активных учебных листов.
2. Собрать просроченные кандзи со всех листов.
3. Исключить зарезервированные элементы.
4. Отсортировать общий список по Score.
5. Рассчитать количество свободных мест.
6. Выбрать первые N элементов.

Главный критерий:

```javascript
Number(a.score) - Number(b.score)
```

То есть первыми идут кандзи с меньшим Score.

При одинаковом Score учитывается порядок учебных листов из CONFIG.

Внутри одного листа сохраняется исходный порядок элементов.

### Ограничение текущей архитектуры

Очередь формируется глобально, но сессии создаются отдельно для каждого учебного листа.

Поэтому сортировка определяет, какие кандзи попали в дневной набор, и порядок внутри отдельной сессии. Она не гарантирует единую последовательность показа между разными учебными листами.

# 9. Временное увеличение дневного лимита

Код механизма и обработчика Telegram присутствует в текущих скриптах.

## 9.1. Принцип

Постоянное свойство:

```text
MAX_DAILY_KANJI
```

не меняется при нажатии Telegram-кнопок.

Временный бонус хранится отдельно.

Состояние:

```text
DAILY_LIMIT_BONUS_STATE
```

Пример:

```json
{
  "date": "2026-09-22",
  "bonus": 5,
  "processedCallbacks": []
}
```

Дата приводится к формату `yyyy-MM-dd` в часовом поясе скрипта.

Если сохранённая дата не совпадает с сегодняшней, бонус считается равным нулю.

Физически удалять свойство каждый день не требуется.

## 9.2. Эффективный лимит

```javascript
maxDaily = baseLimit + bonus;
```

Пример:

```text
Основной лимит: 10
Бонус: +5

Итоговый лимит: 15
```

## 9.3. Функции

```javascript
getDailyLimitDateV1()
```

Возвращает сегодняшнюю дату.

```javascript
getDailyLimitBonusV1()
```

Возвращает действующий бонус.

```javascript
getEffectiveDailyLimitV1()
```

Возвращает сумму основного лимита и бонуса.

```javascript
increaseDailyLimitV1(amount, callbackId)
```

Увеличивает бонус.

Допустимые значения:

* 5;
* 10.

Функция использует Script Lock.

ID обработанных Telegram callback сохраняются в `processedCallbacks`.

Повторная обработка того же callback ID возвращает статус `DUPLICATE`, не увеличивая бонус повторно.

Сохраняются последние 100 callback ID. Это ограниченная история дедупликации, а не бессрочная гарантия для произвольно старых callback.
